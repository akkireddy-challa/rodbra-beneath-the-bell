# Locomotion Assignment — Use Uploaded Animation as Run/Idle

Use when the user has uploaded a custom animation (e.g. a glb generated by an external locomotion tool like Uthana) and asks to *use it as the run animation*, *use it as the idle*, or any phrase that wants the animation to drive how the character moves or stands still.

This is **different from `playCustomAnimation`** (one-shot punches/kicks). Locomotion assignment swaps the engine's persistent state-machine clip — the character keeps using it whenever it's running (or idle).

## Engine model

`AnimationState` (defined in `engine/animation/AnimationContext.js`) has only five values:

| State | When it plays |
|---|---|
| `IDLE` | Character is standing still |
| `WALK` | Character is moving on the ground below the walk/run threshold |
| `RUN` | Character is moving on the ground at or above the walk/run threshold |
| `JUMP` | One-shot during jumps |
| `ATTACK` | One-shot during attacks |

There is no separate `SLOWRUN` / `FASTRUN` state — **both map to `AnimationState.RUN`**, and `walk` / `walking` map to `AnimationState.WALK`. Idle maps to `AnimationState.IDLE`.

The engine only splits walk from run when clips exist for both: with just one of the two assigned, that clip plays at every ground speed. When both are present it picks by movement speed against `walkToRunThreshold` (a `CharacterAnimationConfig` field), with hysteresis so a speed hovering on the threshold can't flicker.

## The data-driven way (prefer this)

Set `locomotionState` on the animation asset itself and the engine does the call for you on load — for the player **and every NPC** that loads the pack:

```json
{ "id": "mAbc123", "name": "Jog", "url": "…/animation.glb", "type": "animation", "locomotionState": "run" }
```

Write it with `edit-world-config` as an `upsertRoot` on `assets` keyed by `id` (read the stored row first and patch it whole). Valid values: `idle`, `walk`, `run`; when several assets claim one state the last one in `assets[]` wins. Remove the field to release the state. The Creator's Record-motion flow and `bitmagic generate animation --video --slot` set this field themselves. Only fall back to the code procedure below when the assignment must be conditional (one character but not another, a specific level, a state the field does not cover).

## Procedure (in code)

1. **Find the asset.** Call `search-assets` with the name the user mentioned. Each animation asset has `id` (= `motionId`), `url`, and `type: "animation"`. If multiple match, ask the user which one with `ask-user-question`.

2. **Pick the state.** From the user's wording:
   - "run", "running", "jog", "sprint", "slowrun", "fastrun", "locomotion" → `AnimationState.RUN`
   - "walk", "walking" → `AnimationState.WALK`
   - "idle", "standing", "stand still" → `AnimationState.IDLE`

3. **Edit the genre's main game file** (e.g. `src/work/Game.ts`) using `file-edit-tool`. Find the existing `loadCustomAnimations()` (or equivalent) method that calls `await animController.loadAllAnimationAssets(...)`. Add a `setAnimationOverride(...)` call **after** the load completes:

   ```typescript
   await animController.loadAllAnimationAssets({ normalizeRootMotion: true, loop: false });
   animController.setAnimationOverride(AnimationState.RUN, '<motionId>');
   ```

   Replace `<motionId>` with the asset's `id` (a string like `mAbc123...`).

4. **Add the import** if `AnimationState` is not already imported at the top of the file:

   ```typescript
   import { AnimationState } from 'engine/animation/AnimationContext.js';
   ```

5. **Re-assigning replaces, doesn't duplicate.** `setAnimationOverride` on the same state simply swaps the active source — there's no separate "remove first" step. To revert to the engine default, call `clearAnimationOverride(state)` instead.

6. Run `type-check`. Reload happens automatically when the user picks up the change.

## Example

User: *"Use 'uthana-fastrun' as the run animation."*

→ `search-assets-tool({ query: 'uthana-fastrun' })` → returns `{ id: 'mFastRunUthana01', ... }`

→ `file-edit-tool` adds (after `loadAllAnimationAssets`):
```typescript
animController.setAnimationOverride(AnimationState.RUN, 'mFastRunUthana01');
```
plus the import if missing.

→ `type-check`.

## Notes

- The asset must already be loaded by `loadAllAnimationAssets()` before the override resolves; calling override before the load returns is a no-op.
- The override persists across the game session. Reload the page to pick up the change.
- For one-shot animations (punch, kick, salute), use `playCustomAnimation` instead — see `@docs animation-assets.md`.
