# Mechanic: platformer

## When to use

Prompts mentioning: platformer, jump, parkour, level, jumping puzzle, Mario-like, side-scrolling, 2D platformer, 3D platformer, obstacle course. The gameplay loop is "navigate from start to end via jumps over obstacles, collecting things along the way."

## Camera / perspective

`cameraMode: 'third-person'` follow camera on an embodied character — always, for 3D platformers. NEVER top-down (jump height and landing points are unreadable from above) and never first-person unless explicitly asked. A "2D / side-scrolling" ask is a different genre entirely (see Variants), not a camera setting.

## Core systems

| System | What it does |
|---|---|
| Jump tuning | Player jump height, duration, double-jump, coyote time, terminal velocity |
| Collectibles | Coins / gems / stars scattered through the level. Increment a counter. |
| Hazards | Pits / spikes / lava. Touching = damage or instant respawn. |
| Lives / health | N lives or HP bar. Death = restart from last checkpoint. |
| Checkpoints | Mid-level respawn points. Player respawns here on death. |
| Level end | Goal at the end of the path. Reaching it = win. |
| Optional: enemies | Slimes / spikes-on-legs / patrolling guards |
| Optional: power-ups | Speed boost / double-jump / temporary invincibility |

## Variants

| Variant | Triggers | Distinct |
|---|---|---|
| **3D platformer** (default for "platformer" / "Mario") | "3D", "third-person", "Mario 64-style" | Free 3D movement, jump mechanic key. Camera follows player. |
| **2D side-scrolling** | "2D", "side-scrolling", "NES", "retro platformer" | The sidescroller template (voxel genre, 2D side-view). The LEVEL is generated by the World-Forger's side-on path (`runWorldForger`) — do NOT hand-build the strip, and do NOT switch to the Physics2D genre (not available in production). Consuming contract: `@docs sideon-forged-levels.md`. |
| **Parkour course** | "parkour", "obstacle course", "American Ninja" | No combat; no enemies; pure traversal challenge |
| **Speedrun / time trial** | "speedrun", "time trial" | Timer; level end shows time; leaderboard |

## Win / lose conditions

| Variant | Win | Lose |
|---|---|---|
| Standard | Reach the level-end goal | Lives reach 0 (or HP reaches 0) |
| Speedrun | Reach goal under target time | Time exceeded / lives reach 0 |
| Collect-em-all | Collect all N collectibles + reach goal | Lives reach 0 |

Default to **standard, 3 lives, 1 level, infinite continues**.

## HUD plan

Required (cross-ref `@docs HUD_ELEMENTS.md`):

- **Lives counter** — top-left: `Lives: 3`
- **Coins / collectibles** — top-right: `Coins: 12 / 30`
- **Optional: HP bar** (if HP-based, not lives-based)
- **Optional: timer** — top-center for speedrun variant
- **"You won" overlay** at level end with stats (time, coins collected, etc.)
- **"You died" overlay** at lives=0 with restart

## Cross-reference to world-plan.md

- **Path / level shape** — usually linear or branching corridor with platforms above/below ground level. Use the voxel CLI (`node bin/voxel.mjs place ... --force-position`; see `@docs voxel-cli.md`) to place platforms at specific Y heights.
- **Start position** — player spawn at the level's entrance.
- **Goal landmark** — at the end of the level. Visual flag-pole / portal / chest.
- **Checkpoints** — flag landmarks at 1/3 and 2/3 of the path.
- **Hazard zones** — gaps in the platform chain, or marked spike regions.
- **Collectibles** — scatter ~20-40 across the level; cluster some near risk for risk/reward.

## Common gotchas

- **Jump tuning is everything.** Default character `runSpeed: 5` is for walking sims. For platformers, set jump height to ~3m, jump duration ~0.5s, gravity ~25 (snappier than realistic). Test with the actual platforms.
- **Coyote time + jump buffering are ENGINE-BUILT** (`COYOTE_S` 0.12s / `JUMP_BUFFER_S` 0.15s in `WalkingAndJumpingMovement`) — do not reimplement them.
- **Moving hazards/platforms: prefer world.json `mechanisms[]` entries** (data-driven, user-editable, persisted; engine-spawned — `@docs moving-platforms.md`). Write code only for behavior the schema can't express, and even then keep the tunables in a `mechanisms[]` entry (`getSpec` + `registerCustom`).
- **Knockback: NEVER `setLinvel`/`applyImpulse` on the player body** — it is kinematic and those are silent no-ops (hazard "hits" that only show a toast). Use `playerController.applyKnockback(velX, velZ, upwardVel)`.
- **Don't forget instant-respawn from hazards.** Touching lava should reset to last checkpoint INSTANTLY (no death animation). Slow respawn = frustration.
- **Use `--force-position` for platforms.** Platforms in the air need exact Y coords, not engine-snapped. The voxel CLI's `place --force-position --y N` is the right tool.
- **Camera matters.** 3D platformers default to third-person follow camera. Don't use top-down (jumping is unreadable). Don't use first-person unless explicitly asked.
- **2D platformer** = the sidescroller lane (voxel genre, side-view camera + Z-locked movement). The World-Forger's side-on path generates the level; the coding pass implements scoring/respawn/goal per `@docs sideon-forged-levels.md`. Never switch a game to the Physics2D genre — it is not available in production.

## Asset references

- Platforms: `platform_floating`, `platform_moving` (use `@docs moving-platforms.md`), `platform_disappearing`
- Hazards: `spike_trap`, `lava_pool` (water with custom material), `spinning_blade`
- Collectibles: `coin`, `gem`, `star` — point-snap, often use `collectible: true` and `placeOnTerrain: false`
- Level-end: `flag_pole`, `goal_portal`, `treasure_chest`
- Power-ups: `mushroom_speed`, `feather_jump`, `star_invincibility`

## Skeleton plan — copy-paste into `mechanics-plan.md`

```markdown
# Mechanics plan — <game name>

## Genre / archetype
3D platformer. Player navigates from spawn to a goal flag via floating platforms over a hazardous lava pit. Collect coins along the way for score. 3 lives, infinite continues.

## Core systems
- Jump tuning: jump height 3m, jump duration 0.5s, gravity 25, coyote time 80ms, no double-jump (V1)
- Collectibles: 25 coins scattered across the level; counter persists across deaths (only resets on game-over → restart)
- Hazards: large lava pit covering most of the world floor. Player respawns at last checkpoint on touch.
- Lives: 3; lose 1 per lava touch / pit fall
- Checkpoints: 2 flags at 1/3 and 2/3 of the path
- Level end: goal flag at the far side; touching it = win

## Win / lose conditions
- Win: reach the goal flag (any number of coins, just survive)
- Lose: lives reach 0 → restart at level start

## HUD plan (`@docs HUD_ELEMENTS.md`)
- Top-left: `Lives: 3`
- Top-right: `Coins: 0 / 25`
- "You won!" overlay on goal touch with `Coins collected: X / 25`
- "Game over" overlay on lives=0 with restart button

## Cross-reference to world-plan.md
- Player spawn at level start (-50, 5, 0). Y=5 is on a starting platform above the lava.
- Goal flag at (50, 5, 0), opposite end. Visual `flag_pole` landmark.
- Checkpoints at (-15, 5, 0) and (15, 5, 0).
- Lava pit: paint terrain Y=0 with `lava` block; platforms are floating environmentObjects with `forcePosition: true` at Y=5.
- Coins: 25 instances of `coin` asset, scattered across platforms and along the path. Each `placeOnTerrain: false`, `collectible: true`.
- Path is mostly linear with 2 alternate routes (one harder for bonus coins).
```
